# SharpChat

Realtime chat for developers, built with .NET 10, SignalR, PostgreSQL, Redis and React.
Project decisions are in [DECISIONS.md](DECISIONS.md).

## Running

Requirements: Docker with Docker Compose.

```bash
cp .env.example .env          # once: then set JWT_SIGNING_KEY (openssl rand -base64 48)
docker compose up --build
```

| Service | Address |
|---|---|
| Web app | http://localhost:3000 |
| API | http://localhost:8080 |
| Liveness | http://localhost:8080/health |
| Readiness (Postgres + Redis) | http://localhost:8080/health/ready |
| Swagger UI (Development only) | http://localhost:8080/swagger |

### Trying the API in Swagger

1. `POST /auth/register`, then `POST /auth/login`, and copy `accessToken` from the response.
2. Click **Authorize** and paste the token (without the `Bearer` prefix). It stays saved across page reloads.
3. Call any protected endpoint, e.g. `GET /users/me`. The access token lasts 15 minutes; log in again (or call `POST /auth/refresh`, which uses the cookie set by login) for a new one.

To look at the data directly: `docker compose exec postgres psql -U sharpchat -c 'select "Id", "UserName", "Email" from "Users";'`

## Development

Requirements: .NET 10 SDK and Docker (integration tests start their own containers with Testcontainers).
The backend lives in `backend/`; run the commands below from there.

```bash
cd backend
dotnet user-secrets set "Jwt:SigningKey" "$(openssl rand -base64 48)" --project src/SharpChat.Api   # once
docker compose -f ../docker-compose.yml up -d postgres redis   # dependencies only
dotnet run --project src/SharpChat.Api
dotnet test
```

Frontend (from `frontend/`, Node 24): `npm install` once, then `npm run dev` (http://localhost:5173). The dev server proxies `/api` to the API at http://localhost:8080 (override with `SHARPCHAT_API_URL`, e.g. `http://localhost:5266` for `dotnet run`). `npm test` runs the component tests, `npm run lint` and `npm run format:check` the static checks.

The browser always talks to the API under `/api` on its own origin: Vite in development and nginx in Docker strip the prefix, upgrade WebSockets and rewrite the refresh cookie path. No CORS is needed.

The JWT signing key is never committed: it comes from user-secrets locally and from `.env` in Docker. The API refuses to start without it.

Database migrations are applied automatically on startup in Development. To add one:

```bash
dotnet tool restore
dotnet ef migrations add <Name> -p src/SharpChat.Infrastructure -s src/SharpChat.Api -o Persistence/Migrations
```

## API

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/auth/register` | — | Create an account |
| POST | `/auth/login` | — | Returns an access token (15 min) and sets the refresh token (14 days) as an `HttpOnly` cookie |
| POST | `/auth/refresh` | Refresh cookie | New access token; the refresh cookie is rotated |
| POST | `/auth/logout` | Refresh cookie | Revokes the session and clears the cookie |
| GET | `/users/me` | Bearer | Current user |
| POST | `/conversations` | Bearer | Create a conversation (optionally with `memberUserNames`) |
| GET | `/conversations` | Bearer | Conversations I'm a member of |
| GET | `/conversations/{id}` | Bearer | Conversation details and members |
| POST | `/conversations/{id}/members` | Bearer (owner/admin) | Add a member by username |
| PATCH | `/conversations/{id}/members/{userId}` | Bearer (owner) | Change a member's role |
| DELETE | `/conversations/{id}/members/{userId}` | Bearer | Remove a member, or leave (own id) |
| GET | `/conversations/{id}/messages?before={cursor}&limit=50` | Bearer | Message history, newest page first (`nextCursor` loads older ones) |

Non-members get `404` for a conversation, so they can't tell whether it exists.

### Realtime (SignalR)

Hub: `/hubs/chat`. Authenticate with the access token (`accessTokenFactory` in the JS client, sent as the `access_token` query string).

| Direction | Name | Payload |
|---|---|---|
| Client → server | `SendMessage` | `{ conversationId, messageId, content }`. `messageId` is a GUID generated by the client, so retries are not duplicated. Returns `{ data: message, error: null }` or `{ data: null, error: { code, message } }` |
| Server → client | `MessageReceived` | The message, sent to every connection of every member (the sender included) |

The refresh token never appears in a response body: it is the `__Secure-sharpchat-refresh` cookie (`HttpOnly`, `Secure`, `SameSite=Strict`, path `/auth`).

Errors use [ProblemDetails](https://www.rfc-editor.org/rfc/rfc9457) with a machine-readable `code` (e.g. `email_taken`, `invalid_credentials`).
